## 4. Решения по бренду: Дрёмиус и Дрёма

Ваше требование: *«Меняю название Дрёмы на Дрёмиус, но сокращённо персонажа продолжат звать Дрёма»*. Разделение, с которым вы согласились и которое теперь записано в `docs/voice.md` (v1.2–v1.4):

- **Дрёмиус — тот, кто отвечает.** Проект, команда, документы, согласия, передача данных Софии, поддержка, граница услуги. Бот поддержки — везде Дрёмиус (там отвечают люди).
- **Дрёма — тот, кто говорит.** Реплики в чате, первое лицо: «я подготовил», «я учёл».
- Проверка в одну фразу: если предложение можно продолжить словами «и несёт за это ответственность» — Дрёмиус; если это голос, обращённый к родителю, — Дрёма.
- **Род.** «Дрёмиус подготовил разбор» — **запрещено**. Действует либо персонаж («я подготовил»), либо люди («команда Дрёмиуса»). Проект сам ничего не делает.
- **PDF плана** — документ, а не разговор: логотип, колонтитул, дисклеймер, подпись — везде Дрёмиус. Ваше решение: *«Дрёмиус везде, включая подпись»*.
- **Первый экран** — единственное место, где имена стоят рядом. Ваша формулировка: «Привет! На связи Дрёмиус, для своих — просто Дрёма 🌙».
- **Меню Дрёмы** — домашнее имя, внутри при этом «Документы Дрёмиуса» и «О Дрёмиусе и команде».
- **Журнал согласий не трогаем.** Текст экрана условий пишется в `ConsentRecord` целиком как то, что человек видел; таблица только пополняется, старые записи остаются со «Дрёмой». Поэтому устаревшие тексты остаются в коде (`termsHealthV1`, `consultConsentV1`, `terms`, `healthScreen`, `welcomeValue`).

### Методология

Ваше требование: *«Давай везде использовать формулировку, что мы используем методологию на основе общедоступных рекомендаций о детском сне»*. «Методология Дрёмиуса» запрещена — причина в честности: авторской методики у проекта нет.

Ваши точные формулировки для родителя:
- «План готовит ИИ-ассистент по нашей методологии…»
- «🌙 разборы готовит ИИ-ассистент по нашей методологии…»

### Голос: ключевые запреты (полностью в `docs/voice.md`)

- Нет приказов, стыда, цифр норм, тревожных слов.
- Нет женского рода в первом лице и голого «мы» (исключение — притяжательное «наша методология»).
- Нет обещания результата и его скорости: «быстро разберёмся» — можно, «быстро наладим сон», «за три дня», «гарантированно» — нельзя.
- Нет заявлений о науке и эффективности, процентов, «научно доказано».
- Нельзя указывать, что чувствовать («не тревожьтесь»); можно снимать тревогу переосмыслением («это не ошибка и не откат»).
- Не притворяться человеком: разбор готовит ИИ-ассистент, проверяет человек.
- Не говорить за Софию: состав услуги описывать можно, обещания от её имени — нет.
- Цены — только из переменных, формат `{цена} ₽`.
- Эмодзи — только из палитры: 🌙 🌟 ✨ ☁️ 💙 💛 🎓 📄 💬 + функциональные.

## 7. Заявка на консультацию (`TZ_consult_request_flow.md`)

Главное изменение: вместо прямой оплаты консультации родитель оставляет **заявку**, команда связывается сама.

**Порядок шагов — по вашему требованию:** *«Давай сначала спрашивать контакт, а потом "Что хотите обсудить"»*.

1. Карточка консультации → «Оставить заявку».
2. Экран согласия на передачу контакта.
3. Контакт: кнопка «Поделиться контактом» или «Напишу команде сам(а)». Чужой контакт не принимается.
4. «Что хотелось бы обсудить?» — текст до 1000 знаков или «Пропустить».
5. Заявка создана, команда получает карточку в `@dremius_team`.

**Ваше требование про таймаут:** *«Если пользователь оставил контакт и в течение 30 минут не ответил на следующий вопрос, считай это тоже последним шагом, создавай заявку»* — сделано: планировщик раз в минуту закрывает такие заявки (`CONSULT_REQUEST_TIMEOUT_MIN`).

**Статусы заявки:** `NEW → CONTACTED (написали) → PAID (оплатили) → CHAT_CREATED (создан чат с Софией) → DONE`, плюс `LOST` с причиной. Статус меняется кнопками на карточке в боте команды и в админке.

**Граница безопасности:** София не получает ничего до оплаты и ничего без записи `SPECIALIST_TRANSFER` в журнале согласий.

**Напоминания по заявке (§3.4 ТЗ) намеренно не включены** — ваше *«Не включай пока»*.

**Админка (этап 4):** список заявок (№, дата, тип, цена, родитель, запрос, статус, сколько ждёт, дневник, выплата), фильтр по типу, карточка с полным запросом и кнопками следующего шага, скачивание пакета заявки. В `/stats` — воронка заявок, считается **по датам** (`contactedAt`, `paidAt`, …), а не по текущему статусу: иначе потерянные заявки исчезали из всех шагов.

## 11. Технический контекст и грабли

Это то, что легко сломать при следующих правках.

**Порядок маршрутизации в `handleIncoming` (`src/engine.ts`).** Callback-кнопки разбираются **до** переключения по стадиям, иначе кнопки под старыми сообщениями перестают работать. Порядок: закрытый режим → `data_*` → отзывы → `menu_example` → меню → `example_*` → рестарт → продолжение анкеты → **шлюз согласия на ПД** → рассылка → `offer_*` → `upsell_*` → контакт → «напишу сам» → комментарий к отзыву → гайд → защита от команд → стадии.

**Шлюз согласия на ПД.** До согласия пропускаются только экраны из `ONBOARDING_STAGES` и callback'и из `ONBOARDING_CALLBACKS`. Любой новый экран онбординга надо добавить **в оба списка**, иначе он замолчит.

**Миграции с enum.** `ALTER TYPE … ADD VALUE IF NOT EXISTS` должен быть в **отдельном файле миграции**, отдельно от миграции, которая новое значение использует: Prisma выполняет файл одной транзакцией. Значения enum нельзя удалить без пересоздания типа — мёртвые значения (`PENDING_PAYMENT`, `CANCELED`, `SPECIALIST`) оставлены и описаны.

**`ConsentRecord` — только пополняется.** Защищено триггером. Тексты экранов пишутся туда дословно, поэтому устаревшие тексты остаются в `texts.ts`.

**Кэш `file_id`** (`src/staticDocs.ts`): ключ — путь + sha256 содержимого. Заменили файл — хэш разошёлся, файл уйдёт заново. `sendCachedDocument(ctx, path, caption?, markup?)` — кнопки вешаются на сам документ, иначе подпись и кнопки разъезжаются. Для фото — `withCachedPhoto` (у фото не один `file_id`, а набор размеров, брать нужно самый большой).

**Прохождения анкеты.** `Session.attempt` + `QuestionnaireAttempt`: рестарт увеличивает номер, старые ответы не смешиваются с новым разбором.

**Неразрывный пробел.** `formatPrice` в `src/texts.ts` использует **неразрывный** пробел, `money()` в `src/web/tablesPages.ts` — обычный. На этом я спотыкался дважды в тестах.

**Карточки с фото в Telegram** — через `link_preview_options = { url, prefer_large_media: true, show_above_text: true }`; убрать превью — `{ is_disabled: true }`.

## 12. Приватность

- Свободные ответы родителя могут содержать сведения о здоровье малыша: в списках обрезаются до 60 знаков, целиком видны только в карточке, в массовые выгрузки CSV не попадают.
- Сведения о здоровье никогда не привязываются к `telegramId` в событиях — только анонимные дневные счётчики (`health_screen_exit`).
- Заметки администратора исключены из выгрузок.
- Переписка о здоровье: бот прямо говорит, что не задаёт вопросов о здоровье и не может его учитывать.
